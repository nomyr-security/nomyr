# Governance

Nomyr is an open-source project. The repository is in Phase 0 foundation work;
this policy describes its current decision process and does not claim that a
formal steering group or staffed security-response team exists.

## Roles and decisions

The GitHub organization and repository settings determine who can administer
the project. The `@nomyr-ai` CODEOWNERS entry is an organizational review
request, not a published list of human maintainers or a guarantee of approval.
The project has not published named human maintainers or ratified a decision
owner roster. No individual role should be inferred from commit authorship.

Routine changes are proposed through issues and pull requests and reviewed by
repository collaborators with applicable access. Changes to architecture,
public contracts, security boundaries, or licensing should be discussed in an
issue and recorded as an accepted or superseded ADR after the authorized project
decision-makers review it. Larger cross-cutting proposals should use the RFC
process in `docs/rfcs/README.md`. A merged proposal is not evidence that every
planned capability is implemented.

Until human decision owners and review thresholds are published, contributors
should treat those governance details as unresolved. GitHub access controls are
authoritative for who can merge; this document grants no access or authority.

## Changes to this policy

Propose material governance changes in a public issue and pull request. State
the affected roles, decision process, security implications, and transition
plan. Repository administrators must apply any corresponding organization or
repository setting changes separately.
